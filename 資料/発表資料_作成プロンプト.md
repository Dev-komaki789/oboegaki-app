# パワポ資料 作成プロンプト

> 下の枠内をそのままコピーして、**`資料/発表資料.md` を添付**して使う。
> 添付できないツールなら、プロンプトの末尾に `発表資料.md` の中身を貼り付ける。

---

```
あなたはプレゼン資料の構成・デザインの担当者です。
添付した「発表資料.md」をもとに、PowerPoint 用のスライドを作ってください。

## 前提

- 発表者：職業訓練校の受講生（1人）
- 聞き手：講師とクラスの受講生。開発経験は人によってばらつきがある
- 時間：15分（うちデモ4分）
- **目的：技術の説明ではなく「このアプリの何がいいか」を伝えること。**
  既存アプリと比べて何が違うか、どこで勝てるかが主題
- 発表の場でスクリーンに映す。手元資料としては配らない

## 構成（16枚。過不足があれば調整してよい）

**時間配分：つかみ1分／デモ4分／競合と勝ち筋5分／設計の根拠3分／まとめ2分**

1. 表紙（アプリ名・キャッチコピー・発表者名）
2. **つかみ**：「それ、前にもお答えしましたよね」。文字は最小限
3. 何を作ったか（コンセプトを1行で ＋ 利用シーン）
4. デモへの導入（「ここから実際に動かします」の1枚。文字は最小限）
5. **既存アプリは3タイプある**（AI生成／パーソナルCRM／業務システムと、それぞれの弱点）
6. **機能で比べる**（比較表。おぼえがきの列を強調）
7. **勝ち筋①「生成」ではなく「記録」に振り切る**
8. **勝ち筋② テキストではなく構造化データで持つ**
9. **勝ち筋③「店舗のもの」ではなく「個人のもの」**
10. **市場の状態**（ToPic Up 評価3件／Dex 6年で3.4万DL／Monica アプリなし）
11. 構造化データだから点数を付けられる（スコアの考え方）
12. その検証（7ケース／Python と完全一致）
13. 個人が持つから構造で分離する（RLS。本人6件／別ユーザー0件）
14. 技術構成（1枚。追加ライブラリ0）
15. やらなかったことと、その理由
16. 最後の1枚（「機能で全部超えるつもりはない。同じ課題にどう設計するかを示したい」）

**5〜10 が本体。ここに一番厚みを持たせる。**
11〜14 の技術は、5〜10 で言った主張の根拠として置く。独立した技術紹介にしない。

## 書き方のルール

- **1スライド1メッセージ。** 言いたいことが2つあるなら2枚に分ける
- **文字を詰め込まない。** 1枚あたり日本語で最大80字程度
- **数字は大きく置く。** 「4秒 → 1秒」「6件 / 0件」のように対比で見せる
- **体言止めを基本にする。** 文章はスライドではなく口で言う
- 箇条書きは**1枚5行まで**
- 表は**3列以内**。それ以上は図か2枚に分ける
- 各スライドに「話す内容メモ」を**発表者ノート**として付ける（スライドには載せない）

## デザイン

アプリ本体と同じ配色を使う（デモとスライドで色が変わると別物に見えるため）。

| 用途 | 色 |
|---|---|
| 背景 | #F7F6F3（紙色） |
| 本文 | #2C2C2C |
| 補足・ラベル | #8B918D |
| 強調・見出しのアクセント | #55806B（くすんだ緑） |
| 面で塗るとき | #EAF0EC（薄い緑）／#FFFFFF（白カード） |
| 罫線 | #EAE7E1 |
| 注意・警告 | #D64545（多用しない。NG話題の話のときだけ） |

- 書体：**Zen Kaku Gothic New**。無ければ ヒラギノ角ゴシック／游ゴシック
- 角丸を使う（14〜16px相当）。直角のカードは使わない
- **影は最小限。** 濃い影やグラデーションは使わない
- アニメーションは**入れない**（切り替えのみ）
- 図を入れるなら**線画**で。3D・アイソメトリック・イラスト素材は使わない

## 禁止事項

- **添付資料に無い数字を足さない。** すべて実測値・調査値なので、盛ったり丸めたりしない
- **競合を貶さない。** 「劣っている」ではなく「そういう設計になっている」と書く
- **技術を主役にしない。** 11〜14 は主張の根拠であって、そこが山ではない
- 「革新的」「圧倒的」などの誇張表現を使わない
- 専門用語を説明なしで使わない（RLS・EMA は1行で補足を付ける）
- 実運用の実績があるかのように書かない（まだ運用していない）

## 出力

各スライドについて、次の形式で出力してください。

---
### スライド N：（タイトル）
**見出し**：（スライドに大きく出す文言・20字以内）
**本文**：（箇条書き。5行以内）
**数字**：（大きく置く数値があれば。無ければ「なし」）
**図**：（必要なら、どんな図か1行で。無ければ「なし」）
**発表者ノート**：（口で言う内容。2〜4文）
---
```

## 使うときのコツ

**① まず14枚を出させて、そのあと直す**

一度で完成させようとせず、**構成が出てきてから「7枚目をもっと簡潔に」**のように指示する方が早い。

**② デモの4分はスライドを作らない**

4枚目（デモへの導入）を出したら、**画面を実機に切り替える。** スライドを見ながらデモを説明すると、聞き手の目が散る。

**③ 発表者ノートは印刷しない**

手元のスマホかタブレットで見る。紙を見ると視線が下がる。

**④ 図が必要そうな3枚**

| スライド | 図の案 |
|---|---|
| 勝ち筋②（構造化） | 「自由記述テキスト → 読んで自分で判断」と「構造化データ → 重複警告・点数化・可視化」を並べた線画 |
| 勝ち筋③（個人所有） | 「店舗が持つ（転職すると消える）」と「個人が持つ（手元に残る）」の対比 |
| RLS | 「ブラウザ → API → DB」と「ブラウザ → DB（RLS）」の2本を並べた線画 |

**上2つは作る価値がある。** 勝ち筋は言葉だけだと流れてしまう。
RLS の図は時間が無ければ省いてよい。

**⑤ 競合名は出してよいが、貶さない**

「弱点」ではなく「**そういう設計になっている**」と言う。
ToPic Up が保存しないのは欠陥ではなく、プライバシーを優先した判断。
**そのうえで「だから蓄積はできない」と事実を言う。**
