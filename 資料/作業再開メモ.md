## 3. 次の一手 ── S-03 お客さん登録

`web/app/people/new/page.tsx` を作る。仕様は §9 S-03。

- **名前のみ必須。** 必須バッジは `danger` 地・白文字・角丸5
- ヘルパー「入力が必要なのはここだけです。」
- 区切り「ここから下はすべて任意」
- 任意5項目：よみがな／年代・性別（select 2カラム）／見た目の特徴／会社名／役職
- 見た目の特徴のヘルパー：「「、」で区切ると、一覧では1つずつのタグに分かれて表示されます。」
- **会社名はサジェスト付き**（`select distinct company from people where company ilike :q||'%'`）
- **写真の登録欄は置かない**

一覧の「＋ 新しいお客さん」ボタンを `/people/new` へのリンクにする（いまは押しても何も起きない）。

保存は Server Action（`app/(auth)/login/actions.ts` と同じ書き方）。`user_id` は書かなくてよい。
**RLS の `with check (user_id = auth.uid())` があるので、明示的に入れる必要がある**点だけ注意
（`insert` 時は自分で `user_id` を渡す。読むときと違って自動では入らない）。

## 6. 設計書と違う判断（引き継ぎ書を読んで迷わないように）

| 箇所 | 判断 | 理由 |
|---|---|---|
| **`auth.users` → `public.users` のトリガー** | §4 に無いが**追加した** | Supabase の認証は `auth.users` にしか行を作らない。橋渡しが無いと `people` を1件も登録できない |
| **RLS の `users` / `keywords` / `topics`** | §4 に SQL が無いので**補った** | `users` のポリシーが無いと自分の行すら読めない |
| **バッジの「+N」** | **実装しない** | 文字幅をサーバー側で見積もる必要があり割に合わない。CSS の `max-h-16` で2行に制限し、3行目以降は静かに隠す |
| **検索は入力するたびに走る** | §9 に記載は無いが**そうした** | スマホ・タブレット中心のため。Enter を押す動作が一手間になる |
| **タブレット5画面** | **作らない** | 5日では不可能。発表はスマホで通す |

## 7. ハマった点（同じ症状が出たとき用）

| 症状 | 原因 | 対処 |
|---|---|---|
| `モジュール '@supabase/ssr' が見つかりません`<br>`名前 'process' が見つかりません` | `web/node_modules` が無い | `cd web && npm install` → `TypeScript: Restart TS Server` |
| `The default export is not a React Component` | ファイル編集中の一時的な状態 | 書き終われば消える |
| `Invalid login credentials` | **画面のエラー文言は1種類に統一してある**ので原因が分からない | `actions.ts` の `console.error` を `npm run dev` のターミナルで見る |
| Table Editor で行が見えない | RLS が効いている**正常な状態** | SQL Editor（管理者権限）からは見える。故障ではない |
| バッジの楕円が潰れて中の文字が折り返す | **flex は入りきらないとき、次の行へ送る前にまず縮む** | バッジに `shrink-0 whitespace-nowrap` |
| 変換途中のローマ字で検索が走る | IME の変換中も `onChange` が発火する | `compositionstart` / `compositionend` で変換中は検索しない（`SearchBox.tsx` 参照） |
