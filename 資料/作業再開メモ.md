## 3. PWA ── 解決済み（2026-08-25）

Android の Chrome で **「アプリをインストール」が出るようになった。**
ホーム画面のアイコンから起動すると、**アドレスバーもブラウザの戻るボタンも消える。**

### 原因は1つだけだった

**`/manifest.json` が HTTP 307**（`/login` へリダイレクト）になっていた。
`middleware.ts` の matcher に `manifest.json` を除外し忘れており、未ログインの
リクエストが認証チェックに引っかかっていた。

**Android は manifest が読めないと PWA として扱わず、ショートカット扱いになる。**
アイコンもグレーの代替（「V」の文字）に落ちる。これがその症状だった。

matcher の除外に `manifest.json` / `apple-touch-icon.png` / `icon-*.png` を追加して解決。

### Service Worker は不要だった

当初「Chrome は `fetch` を扱う Service Worker を要求する」と見込んで用意しようとしたが、
**manifest を直しただけで出た。** 現在の Chrome では SW 無しでインストールできる。
`sw.js` は作っていない（§12-8 が警告する「キャッシュ周りで詰まる」を避けられた）。

### 判定と注意

- **メニューの文言が判定基準。**
  「アプリをインストール」＝ manifest 有効／「ホーム画面に追加」だけ＝ 読めていない
- **Chrome は「少し使ったサイト」にだけ提案する。** 開いた直後には出ない。30秒ほど操作する
- **アイコンを差し替えたら、ホーム画面から一度削除して追加し直す。** Chrome がキャッシュを持つ

### 発表で使うときの注意

**ホーム画面から起動したアプリは、ブラウザとは別のデータ領域を持つ。**
ブラウザでログイン済みでも、アプリ側は未ログインから始まる。
**当日、ホーム画面版で先にログインしておくこと。**

## 6. 設計書と違う判断（引き継ぎ書を読んで迷わないように）

### DB

| 箇所 | 判断 | 理由 |
|---|---|---|
| `auth.users` → `public.users` のトリガー | §4 に無いが**追加** | Supabase の認証は `auth.users` にしか行を作らない。橋渡しが無いと `people` を1件も登録できない |
| RLS の `users`／`keywords`／`topics` | §4 に SQL が無いので**補った** | `users` のポリシーが無いと自分の行すら読めない |

### 計算

| 箇所 | 判断 | 理由 |
|---|---|---|
| 日数の差 | `Math.round(ミリ秒/86400000)` → **`differenceInCalendarDays`** | `talked_at`（date型）と `new Date()`（時刻あり）を混ぜると夜間に1日多く数え、減衰の境界が早く来る |
| `lib/recalc.ts` を新設 | §6 の④⑤⑥を共通化 | 保存・修正・削除で同じ計算をする。2箇所に分かれると必ずずれる |
| 記録が0件になった話題 | **行ごと削除** | 残すとスコア0の泡がバブルの枠を1つ無駄にする |

### 画面

| 箇所 | 判断 | 理由 |
|---|---|---|
| バッジの「+N」 | **実装しない** | 文字幅をサーバーで見積もる必要があり割に合わない。CSS の `max-h-16` で2行に制限し、3行目以降は静かに隠す |
| 検索 | **入力するたびに走る** | スマホ・タブレット中心のため。変換中は検索しない（`compositionend` で確定時のみ） |
| 一覧のよみがな | **名前の上**（モックアップは横並び） | 横並びだと名前に使える幅が176pxしかなく「中村 あゆみ」程度で省略される |
| 明細の点数 | `text-name` / `accent-500` | §9 は「控えめに小さく」だが `text-caption` では読めなかった。話題スコア（32px）より小さい関係は維持 |
| 画面幅の上限 | 390px → **430px** | §8 の基準は iPhone 390 だが、上限を 390 に固定すると大きい端末で両端が余る |
| 時系列／話題別 | **クライアント側で切り替え** | 開発ログ06 は「クエリで持つ」としていたが、切り替えのたびに4本のクエリを投げ直しており体感に出た。URL は `history.replaceState` で維持 |
| バブルの半径 | `range([24, 64])` → **`range([0, 64])`** ＋ 透明な当たり判定24px | §9 の「24px」の根拠は「指で押せる下限」。見た目の下限にすると0点でも直径48pxになり、48〜128pxの2.7倍幅に圧縮されて差が読めない（最大/最小 1.75倍 → 3.16倍） |
| 一覧のバッジ | **名前の列の外に出す**（モックアップは列の中） | よみがなを上に移して名前の列が3行になった一方、右カラム（3日前/前回）は2行で終わり、バッジの右隣が空いていた。列の外に出すと 176px → 286px（+62%） |
| `content` の表示 | **`whitespace-pre-wrap`** | 改行を入れて保存できるのに、HTML の既定では空白1つに潰れて消えていた。`pre` ではなく `pre-wrap`（改行は残し、長い行は折り返す） |
| キーボードを閉じる（M-12） | **`touchmove` で判定・全画面に適用** | スクロール量（48px）で判定すると、お客さんが6人だとスクロールできる量が足りずゆっくり動かしても閉じなかった。入力欄そのものをなぞる操作（文字選択・スライダーのドラッグ）は除外 |

### 仕様に無い追加

| 追加 | 理由 |
|---|---|
| お客さんの編集・削除 | §9 S-04 に「編集」リンクの定義はあったが行き先が未定義だった |
| **記録の修正・削除** | **実機でスライダーが飛び、意図と違うスコアで保存される事故が起きた。** 帯をタップすると値が飛ぶのは `range` の標準挙動で防げないため、あとから直せる手段が要る。記録する画面にも ±1 ボタンを追加 |
| 設定画面（ログアウト） | ログアウトの手段が無く、別ユーザーでの確認にシークレットウィンドウが必要だった |

### ページ遷移

| 種類 | 方式 |
|---|---|
| 戻る・閉じる・お客さん一覧・話題に戻る | **pop**（`router.back()`） |
| タブ（お客さん情報 ⇄ 話題） | **replace**（横移動なので履歴を積まない） |
| 保存・更新・削除・ログイン後 | **replace**（`RedirectType.replace`。入力画面が履歴に残らない） |
| 一覧→詳細、泡→話題詳細 | push（通常の前進） |

> **`replace` は履歴の一番上を差し替えるだけで、スタックを縮めない。**
> 一度「行き先つきリンクは replace で直接飛ぶ」にしたが、お客さんを見るたびに履歴が
> 1つずつ伸びた。**縮められるのは pop だけ。**

## 7. 性能について（2026-08-25 計測）

実機で**1タップ4秒**だったものを**1秒以下**にした。

| 対処 | 効果 |
|---|---|
| **Vercel の実行リージョンを東京（hnd1）に** | **4秒 → 1秒。** 既定はアメリカ東部で、1問い合わせごとに太平洋を往復していた |
| 問い合わせを `Promise.all` に | `/people/[id]` 3回→1回、`/topics` 4回→1回、`/record` 4回→1回 |
| `loading.tsx` を5ルートに | 押した瞬間に骨組みが出る |
| 主要導線に `prefetch={true}` | 画面に入った時点で先に取りに行く |
| 時系列／話題別をクライアント切り替えに | 往復ゼロ |

**下限は 126ms**（`/login` の応答＝DBクエリ無し）。コールドスタートは 310〜685ms で、
Vercel 無料枠では避けられない。**発表直前に何度かタップして温めておく。**

参考：CSS 94KB（`@font-face` 364個）／JS 154KB。

| 症状 | 原因 | 対処 |
|---|---|---|
| `モジュール '@supabase/ssr' が見つかりません` | `web/node_modules` が無い | `cd web && npm install` → `TypeScript: Restart TS Server` |

| 変換途中のローマ字で検索が走る | IME の変換中も `onChange` が発火 | `compositionstart`／`compositionend` で判定 |
