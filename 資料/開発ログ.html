設計書 v7 に合わせて書き直す

仕様が v6 から v7 に更新された。差分を反映し、引き継ぎ書を一次資料から起こし直した。

  • visits テーブルを削除して全6テーブルに。「今日会った」は records.talked_at から引ける。同じ情報を2箇所に持つとズレる
  • 外部キーの ON DELETE を8本すべて確定。 keyword_id だけ SET NULL ── CASCADE にするとキーワードを消しただけで会話の記録まで消える
  • topic_master_id は RESTRICT。「食べ物」という名前を消しただけで食べ物の会話が全部消えるのは事故になる
  • 初期話題マスタ10件の並び順を確定。上ほど誰にでも当てはまり、下ほど当たれば強いが人を選ぶ
  • 見た目の特徴は text のまま保存。分割は表示時だけ。集計しないなら別テーブルにする理由がない

people.last_talked_at と topics.score は records から導出できる冗長カラムだが、読み取り頻度が高いので意図的に持つ、という整理も明文化された。

Figma バリアブルを取り込む

Figma で定義済みの色を Tailwind の @theme に変換した。既存23色は完全一致。バブル色5つが新規で入っていた。

バブル色が計算式から4段階パレットに変わっていた

カラー仕様（v5）には連続計算式が書かれていたが、Figma には離散4段階＋前回話した色が定義されていた。OKLCH に変換して比較した。

色相と明度の幅（0.30）は一致するが、全体が 0.045 明るく、薄い側の彩度が高い。手で調整した版と判断し、Figma を採用した。

「score 60以上で白文字」が成立しなかった

カラー仕様のこのルールを4段階に当てはめると、コントラストが足りない帯が出る。全組み合わせを計測した。

プロジェクト構成を決める

設計資料とコードを混ぜず、履歴は1つのリポジトリで追えるようにした。

oboegaki-app/            ← git リポジトリのルート
├── web/                 ← コードはすべてこの中
├── モックアップ/          ← smartphone / tablet
└── 資料/                 ← 設計書・定義書・このログ

コードを web/ に分ける理由。ルートに展開すると node_modules/ や設定ファイル群が並び、整理した2フォルダがその中に埋もれる。web/ を足すだけなら既存ファイルを1つも動かさずに済む。

git をルートに置く理由。開発中に設計書が更新されるので、その履歴も追いたい。create-next-app は既定で web/ の中にリポジトリを作ってしまうため、--disable-git で抑止してからルートで git init する。

URL 構造はタブとトグルで扱いを分ける

画面URL理由
S-04/05 情報タブ/people/[id]時系列／話題別は並べ替えでしかなく、どこにも遷移しない。だから状態（クエリ）で持つ
　└ 話題別?mode=topic
S-06 バブル/people/[id]/topics泡から S-07 へ進み、戻ってくる。ルートが分かれていればブラウザの戻るがそのまま効く
S-07 話題詳細/people/[id]/topics/[tid]「誰の」「どの話題か」が URL に出る
S-08 記録する/people/[id]/record「保存して次を書く」が同じ URL に戻るだけで済む

app/api/ を作らない。通常はクライアントに DB を直接触らせないため API を挟むが、RLS が DB 側で権限を保証しているので Server Component から Supabase を直接呼べる。API ルートを1本も書かずに済む。

環境構築

ここから先は再現手順。同じ環境をもう一度作るならこの順に実行する。

1. 雛形の生成

cd ~/Documents/oboegaki-app

npx create-next-app@15 web \
  --typescript --tailwind --app --eslint \
  --no-src-dir --use-npm --import-alias "@/*" --disable-git --yes

--no-src-dir は src/ を作らない指定。App Router では app/ が特別扱いなので、1階層深くなるだけで利点が薄い。--import-alias "@/*" で @/lib/supabase のように書けるようになり、ファイルを移動しても import を直さずに済む。

2. 依存パッケージ

cd web
npm i @supabase/supabase-js @supabase/ssr d3-force d3-scale date-fns
npm i -D @types/d3-force @types/d3-scale
cd ..

@types/* は TypeScript に部品の使い方を教える説明書。d3 は元々 JavaScript で書かれていて型情報を持たないため別途入れる。コードを書く間だけ必要で完成品には含まれないので -D を付ける。

3. git の初期化

git init
git config core.quotepath false

core.quotepath false は日本語ファイル名をそのまま表示させる設定。入れないと git status で 資料/ が \350\263\207\346\226\231/ のような数字列になる。

4. デザイントークンの流し込み

web/app/globals.css の @theme にトークン72個（色33・タイプスケール10・角丸4ほか）を定義し、web/app/layout.tsx でフォントを読み込む。内容は引き継ぎ書 §12-4 / §12-5 に全文がある。

.gitignore は2つに分けた

.gitignore は自分の置かれたフォルダから下に効き、パスはそこからの相対として読まれる。1つにまとめることもできるが、web/.gitignore は Next.js が用意した28行の完成品なので、書き写さずそのまま使う。

ファイル担当中身
web/.gitignoreNext.js アプリとして無視すべきもの自動生成のまま。触らない
.gitignore（ルート）リポジトリとして無視すべきもの.DS_Store の2行だけ

判断基準は「web/ だけを他所に持っていっても必要か」。必要なら web/ 側、このリポジトリ固有ならルート側。
